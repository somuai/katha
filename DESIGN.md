# Katha — remember the record, verify the change

**Problem.** The challenge's Monday/CRM questions combine two different jobs: recovering an original record and checking an external change. Similarity cannot establish chronology; a current price cannot establish when it changed.

**Two deep modules.** Turns owns atomic acceptance, ordering, execution and replay. Evidence Library owns originals, extraction, recall, correction and deletion. One Node process owns a local SQLite connection, acquiring exclusive ownership before migrations or restart recovery. Network work holds no transaction. Original messages and FTS commit before asynchronous MiniLM enrichment. Retrieval combines calendar constraints, lexical/vector rankings, neighbors and correction lineage; selected files retain priority. IANA-zone half-open intervals distinguish event time, ingestion time and correction effective time.

**Durability.** Request identity is checked before conversation-tail validation. Replaying a request retrieves its receipt; deliberate Retry creates a fresh linked turn with a new cutoff. Deleted originals cannot silently return through retry. SSE disconnection detaches the observer, while Stop explicitly cancels. Process restarts mark unfinished turns interrupted without replaying quota-limited calls. Deletion advances an epoch and invalidates dependencies; late generation/index callbacks cannot restore removed sources. Document references link literal user mentions to source versions, rather than treating earlier assistant claims as identity.

**One agent tool.** Only `web_search` is model-controlled. Optional OAuth connections import records selected by the user; the model cannot browse mailboxes or invoke arbitrary MCP tools. Provider adapters hide authorization, rate limits and cache behavior. This preserves the challenge boundary but means connected records are snapshots requiring explicit refresh.

**Evidence before claims.** Bounded parallel search retains raw-page passages where available, observation dates and extraction provenance. Comparisons distinguish matching now, unknown change timing, dated change, conflict and insufficient evidence. Failed searches never establish stability. Complete explicit offers use deterministic commercial-term parsing; missing terms are not guessed. Mixed requests assess prices and releases separately for each vendor, scoped by visible evidence rather than query labels. Dates require verbatim effective-date evidence; a release date cannot date a price change. The host validates comparisons before rendering prose.

Invalid plan shapes, source quotations, citation IDs or comparison links get a bounded repair, then fail closed. Version-risk web prose receives a bounded same-model qualification review sharing that repair allowance; drafts survive quota retries. This adds requests and can still miss semantic errors; it is not independent certification. Missing inference returns labelled source-only partial evidence, never a completed model answer. Progress and usage are reported honestly; completed entity assessments survive a same-process quota retry, not a crash.

**Trade-offs and rejected designs.** A giant recent-history prompt loses dated recall and grows cost. A workflow engine and remote vector database add operational machinery without helping this local challenge. SQLite simplifies judge setup but exclusive ownership prevents simultaneous database inspectors. Local embeddings cost a first download; hosted open-weight models still have free-tier quotas. Per-vendor assessments improve coverage at the cost of extra requests and quota delay. CSV aggregates are bounded deterministic preparation; scans/images require labelled model interpretation.

**Evidence.** Public-interface tests use real temporary SQLite/files and fake only external providers. Versioned answer/source/claim ledgers separate retrieval, factual support, task completion and quota failures. See docs/STATUS.md: no production accuracy, clean current-default gate or competitor superiority is claimed.
