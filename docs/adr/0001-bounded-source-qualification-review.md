# Bounded source-qualification review

Status: implemented with deterministic public-turn proof and limited text-candidate observations; default and full release validation remain pending.

The fixed-set review exposed prose that repeated old parameter restrictions or merged browser-specific errors into a universal rule. Exact citation IDs and verbatim quotes did not catch this. Stronger generation instructions alone still failed a targeted replay.

For ordinary web prose, use one same-model source-qualification/factual-support review before publication. The initial version-risk marker selector missed an unestablished billing mechanic, so the app no longer depends on those markers: the host’s ordinary-answer path plus web evidence triggers review. Structured comparisons retain their separate host validation; private-file and ordinary memory answers do not enter this path.

The review returns a small validated supported/issues record, not a replacement answer or private reasoning. A rejected draft may consume the same single repair allowance already used for quotation/citation repair. A revised draft is reviewed again; rejection or malformed review fails visibly rather than publishing unsupported text. This is not independent semantic certification: a same-model reviewer can still miss unsupported material or reject a supported answer.

Both generation and review use the existing model limiter, active deadline and quota-wait policy. The bounded five-minute/32-entry draft cache preserves an unpublished draft across same-process quota retries. A crash still interrupts the turn; cancellation/deletion validation remains authoritative. Known completed-response usage includes review and repair; unknown failed-attempt usage stays unknown.

Trade-off: selected web questions take an extra model request, or three extra requests if review requires a repair and re-review. No extra agent tool, new provider, paid fallback or public interface is introduced. Full grounding accuracy, added latency and free-quota impact must be measured on the frozen evidence, not inferred from deterministic tests.

The targeted candidate replay also exposed an existing adapter omission: the host already computed `verification`, but the provider input dropped it. Propagate that decision explicitly. An ordinary explanation requires `comparisons: []` and bypasses historical offer parsing/per-vendor verification. An accidental comparison gets the same bounded repair, not a fabricated baseline or an irrelevant “cannot establish a change” answer. The evaluator records actual planning/generation/qualification-review HTTP phases without headers or provider reasoning fields, making added calls observable.

Ordinary explanations use a shorter dedicated prompt instead of carrying unused historical commercial-comparison schemas. This reduces context pressure and makes the host path less ambiguous. The evaluator publishes only whitelisted aggregate input/output/total usage and visible review findings; headers, raw provider reasoning fields and reasoning-token detail structures are excluded. Any latency benefit remains a versioned observation to measure, not a guaranteed speed claim.

An English presentation-preference question (“Would you like a general overview…?”) cannot terminate an ordinary public current-information turn. The host records that it ignored this optional choice and proceeds. This narrow guard does not suppress genuine missing-entity questions, historical ambiguity, or private-record clarification, and is not a multilingual semantic classifier.

A subsequent replay reproduced the original microphone overgeneralization even after review. Diagnosis showed that both model requests lacked the retained `TypeError` counter-passage: a core 1,800-character selection and provider 900-character selection had successively removed it. Web observations now reach the provider as retained bounded text; the provider owns the small model-visible window. Web definition-list paragraphs are split into shorter sentence excerpts with their copied labels and explicit omission markers. Up to 16 definition labels enrich only local excerpt ranking, never external search queries. Original retained text remains the quote-validation source.

A public-Turn regression using the frozen MDN capture confirms that both generation and review receive `TypeError`, `NotAllowedError` and the secure-context requirement within 900 characters. Private/PDF/CSV excerpt handling is unchanged. This fixes the observed information loss, not every possible omission within a finite excerpt budget.

### Coherent excerpt and citation follow-up (`a251224`)

A real captured Tavily parameter page exposed a second context-loss case: its best-effort caveat survived but the zero/live value sentence was displaced by site configuration. Web-only excerpting now removes recognized docsConfig shell paragraphs and repeats short subject leads with explicit gap markers. Raw observations and private-document selection remain unchanged. Public-Turn fixtures inspect both generation and review inputs within the existing 900-character bound. Shared citation syntax handles explicit Unicode/source-prefixed/internal references without treating code literals as citations; it does not establish entailment. The targeted live replay fixes freshness explanation but still exposes unsupported date semantics despite review approval. See `docs/evaluations/coherent-excerpts-review.md`; same-model review remains a bounded filter, not a truth guarantee.
